# 主要功能与技术特点生成

针对 R11 申请表第 4 页的两个核心生成字段，产出可直接填报的草稿文本。适合在填报前单独打磨这两段文字、或对 `/fill` 产出的草稿进行改写迭代时使用。

目标项目目录：`$ARGUMENTS`（为空则为当前工作目录）

写作规范：`software-reg` skill 第 5 节（5.1 主要功能、5.2 技术特点）；字段官方说明见 references/page4-软件功能与特点.md，引用时不得改写。

## 执行步骤

### 1. 收集素材（只读）

- **功能素材**：README 功能列表、路由/菜单定义、控制器/服务模块划分、数据库表结构反映的业务域
- **技术素材**：技术栈与架构模式（前后端分离/微服务）、关键技术（缓存、消息队列、算法）、AI 能力、移动端形态、性能与安全设计

素材必须来自实际扫描，**不得虚构项目没有的功能或技术**。

### 2. 生成"软件的主要功能"（500–1300 字，有下限）

- 按功能模块分条描述，覆盖系统主要功能点；忌只写概括性一段话（容易不足 500 字）
- 语气：客观陈述，"本软件/系统用于……，主要功能包括：1.……"
- 生成后用 `wc -m` 核实字数：不足 500 字按模块扩写，超过 1300 字压缩次要模块

### 3. 生成"软件的技术特点"

- **类别勾选**：从 15 项复选列表（APP、游戏软件、教育软件、金融软件、医疗软件、地理信息软件、云计算软件、信息安全软件、大数据软件、人工智能软件、VR软件、5G软件、小程序、物联网软件、智慧城市软件）按实际勾选，可多选，并逐项说明勾选理由
- **文本（≤100 字）**：概括架构与技术亮点，不堆砌功能列表

### 4. 输出

```markdown
# 主要功能与技术特点草稿：<项目名>

## 软件的主要功能（实际字数：N / 500–1300）
<正文>

## 软件的技术特点
勾选类别：<类别 + 勾选理由>
文本（实际字数：N / ≤100）：<正文>

## 素材依据
<每段文字对应的扫描来源：文件/模块，便于用户核对未虚构>
```

## 边界

- 只读，不修改目标项目的任何文件
- 输出为草稿，提示用户审阅修改后再填报；字数核验结果必须标注
- 目标目录不存在或不是代码项目时，直接说明并停止
