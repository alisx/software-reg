# 软著申请表填报草稿

分析目标项目，为中国版权保护中心 R11 申请表（第 2 页软件申请信息、第 3 页软件开发信息、第 4 页软件功能与特点）的每个字段给出建议填报值和推断依据，输出一份可直接对照填报的草稿。

目标项目目录：`$ARGUMENTS`（为空则为当前工作目录）

判定依据：`software-reg` skill 第 3 节"字段自动推断映射"和第 2 节硬性规范。逐字段官方说明原文见 skill 的 references/ 下三页字段文档（page2/page3/page4），引用说明文字时不得改写。

## 执行步骤

### 1. 扫描项目（只读）

用 Bash / Glob / Grep 收集事实，全部以实际扫描结果为准，不得臆测：

- **代码量与语言分布**：按语言统计行数（排除空行；排除 `node_modules`、`vendor`、`.venv`、`dist`、`build`、`target`、`.git` 等第三方与生成物目录），说明统计口径
- **版本信息**：`package.json`、`pyproject.toml`、`Cargo.toml`、`pom.xml` 等清单中的 name/version；git tag
- **git 日期**：首次提交与最后提交日期（推断开发完成日期）；首次公开发布记录（推断发表状态）
- **运行环境**：Dockerfile、docker-compose、部署文档、CI 配置 → 运行硬件环境 / 运行操作系统 / 运行支撑环境
- **开发环境**：构建工具、IDE 配置、开发依赖 → 开发环境 / 开发工具 / 开发操作系统
- **功能素材**：README 功能列表、路由/菜单定义、控制器/服务模块划分、数据库表结构 → 主要功能、开发目的、面向领域
- **技术栈**：架构模式、中间件、缓存、消息队列、AI 能力等 → 技术特点

### 2. 逐字段生成建议值

按 references 三页文档的字段顺序逐项输出。每字段给出三项：**建议填报值 / 推断依据 / 置信度**：

- ✅ **自动推断**：扫描事实支持，可直接填报
- ⚠️ **建议待确认**：给出建议值，需用户定稿（如软件全称、发表状态）
- ❌ **需用户提供**：无法从代码推断（如开发方式、著作权人、证件信息），列出需要准备什么

硬性约束（生成值必须满足，不满足时自行修正并标注）：

- 字数上限：软件全称 ≤100 字、简称 ≤50 字、各环境字段 ≤50 字、开发目的 ≤50 字、面向领域 ≤50 字、技术特点文本 ≤100 字、其他编程语言 ≤120 字
- **软件的主要功能 500–1300 字**（有下限）：按 skill 第 5.1 节分模块生成，生成后用 `wc -m` 核实字数并标注实际字数；不足 500 字时按功能模块扩写
- 版本号为 `V数字` 或 `数字` 格式；简称没有就留空，**不要填"无"**
- 开发完成日期不得晚于申请日；已发表时首次发表日期不得早于开发完成日期
- 编程语言按 21 项复选列表勾选；列表外语言（TypeScript、Kotlin、Rust 等）写入"其他编程语言"
- 开发方式为非单独开发时，提示对应权属证明文件（见 skill 第 2.4 节表格）

### 3. 输出填报草稿

```markdown
# 软著申请表填报草稿：<项目名>

## 第 2 页：软件申请信息
| 字段 | 建议填报值 | 置信度 | 依据 |

## 第 3 页：软件开发信息
| 字段 | 建议填报值 | 置信度 | 依据 |

## 第 4 页：软件功能与特点
| 字段 | 建议填报值 | 置信度 | 依据 |

### 软件的主要功能（实际字数：N）
<500–1300 字正文>

### 软件的技术特点
勾选类别：<15 项中的勾选建议>
文本（实际字数：N，≤100）：<正文>

## 需用户确认 / 提供
<⚠️ 待确认项清单：建议值 + 需要用户拍板的点>
<❌ 用户提供项清单：需要准备的材料或信息>
```

## 边界

- 只做分析与生成，不修改目标项目的任何文件
- 开发方式、著作权人、首次发表地点等不可推断信息不臆测，列入"需用户确认 / 提供"
- 输出的长文本（主要功能、技术特点）为草稿，提示用户审阅修改后再填报
- 目标目录不存在或不是代码项目时，直接说明并停止
