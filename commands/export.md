# 软著申请材料导出

在目标项目中生成一个固定目录 `软著申请材料/`，把 R11 申请所需的填报信息和鉴别材料草稿一次性输出为成稿文件，用户可直接核对、转 PDF 后使用。

目标项目目录：`$ARGUMENTS`（为空则为当前工作目录）

依据：`software-reg` skill 第 2 节硬性规范、第 3 节字段推断映射、第 5 节写作指导；字段官方说明见 references/ 下三页字段文档，引用时不得改写。

## 执行步骤

### 1. 前置检查

先按 `commands/check.md` 第 1、2 节做快速判定：

- 全部通过（无 ❌）→ 直接导出
- 存在 ❌ 项 → 列出问题并说明这些项会在导出文件中标注"待整改"，由用户决定是否继续；用户放弃则停止

### 2. 准备导出目录

固定位置：`<目标项目根>/软著申请材料/`。

- 目录不存在 → 创建
- 目录已存在 → 列出将被覆盖的文件，经用户确认后再写入；用户要求保留旧版时，改为写入 `软著申请材料-YYYYMMDD-HHMMSS/`

只写这个目录，不修改目标项目的任何其他文件。

### 3. 生成导出文件

| 文件 | 内容 | 生成方式 |
|---|---|---|
| `00-填报指引与材料清单.md` | 每个文件的用途、填报/上传位置、用户必办事项、一致性核对清单 | 汇总 |
| `01-申请表填报信息.md` | 第 2/3/4 页全字段填报草稿（格式同 `/fill` 输出） | 按 fill.md 步骤 1、2 扫描生成 |
| `02-主要功能与技术特点.md` | 主要功能（500–1300 字，`wc -m` 核验）+ 技术特点（类别勾选 + ≤100 字文本） | 按 describe.md 生成 |
| `03-源程序鉴别材料.txt` | 前 30 页 + 后 30 页源程序，分页排版 | 见下方排版规则 |
| `04-文档鉴别材料.md` | 用户手册/设计说明书草稿，截图处留占位标记 | 从 README/现有文档扩写 |

**源程序排版规则**（对应 skill 第 5.3 节与官方原文要求）：

- 选码范围：自主核心代码（可按功能主次排序）；排除第三方库、自动生成代码、配置文件与空行
- 每页 ≥50 行，页之间用分页标记 `===== 第 N 页 =====` 分隔；每页页眉行标注软件全称 + 版本号（与申请表一致，skill 第 2.1 节一致性要求）
- 总量不足 3000 行（约 60 页）→ 全部放入，并在 `00-填报指引与材料清单.md` 中注明"源程序不足 60 页，已提交全部"
- 无法推断软件全称/版本号时，页眉留 `【软件全称待确认】` 占位，并在指引文件中列为用户必办

**如实声明**：导出的是 TXT/MD 草稿。提交要求 PDF 格式，指引文件中写清转换方式（粘贴到 Word/WPS 调整字体后导出 PDF，逐页核对行数与页眉）；若环境中有 pandoc 等工具可代为转换 PDF，转后仍提示用户逐页核对。

### 4. 导出后输出摘要

```markdown
# 导出完成：<目标项目>/软著申请材料/

| 文件 | 状态 | 备注 |
（状态：✅ 可直接使用 / ⚠️ 含待确认占位 / ❌ 待整改项未解决）

## 用户接下来要做的事
1. <按顺序列出：定稿名称/版本 → 补截图 → 转 PDF → 核对一致性 → 网上填报>
```

## 边界

- 只写 `软著申请材料/` 目录，不修改目标项目其他文件；覆盖前必须列出文件并获确认
- 内容不得臆造：无法推断的字段留占位并列入用户必办，不编造名称、日期、证件信息
- 开发方式、著作权人等非代码可推断信息在导出文件中保持"待确认"标注
- 目标目录不存在或不是代码项目时，直接说明并停止
